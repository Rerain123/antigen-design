用户提供 `DeepTMHMM-Academic-License-v1.0.zip`，原 ZIP 保留在下载目录。包 SHA-256：
`0a7a6c5d009e928c2e09bd0f225ad290166c6e67ebff5fb59145639484fcbd82`。

不声称已独立验证发布者签名，也没有重新分发授权包。

独立 Docker 镜像按包内依赖建立：Python 3.8.20、PyTorch 1.5.0+cu92、fair-esm 0.4.0、BioPython 1.79、

## 4. 原始格式与后续适配要求

1. **三行文件。** 每条为 `>ID | TYPE`、输入序列、六类标签串；必须检查唯一 ID、输入对应、序列逐字一致与等长。
   不能套用前序历史四行资料的解析方式。
2. **区段表。** 虽名为 `TMRs.gff3`，本包实际输出 ID/type/start/end 四个有效字段和四个尾空字段，
   另含长度/TMR 元数据；不是通用九列 GFF3。区间为 1-based 闭区间，须与连续同标签区段逐段一致。
3. **计数。** 原包 TMR 数同时包含 M 和 B；项目 tm_count 只统计连续 M 区段，outside_length 只数 O 残基。
   P/B 原始串与区段完整保留，项目结果须 topology=null、unreliable、failure 级 WARNING、禁止自动交接。
   本批只生成证据检查及守卫预期，生产适配器和下游 S-16/S-19/S-27/膜蛋白门控尚未实现。
4. **概率。** 单输入才生成图和概率 CSV；CSV 索引从 0 开始，不能与项目区段坐标混用。
   本批检查列、行数、索引、氨基酸、有限值及 [0,1] 值域；概率和的差异只记录，不凭空指定科学容差。
5. **文件名。** 原程序直接以输入 ID 写概率文件。短样本 ID 的 `|` 在 Windows 挂载目录实际表现为 U+F07C；
   生产封装应使用内部安全 ID 并保留原 ID 映射。源码还通过字典保存 ID，重复 ID 存在覆盖风险；
   检查器已测试拒绝重复记录，不把源码发现称为执行过的模型故障。
6. **原报告。** 工具生成的 Markdown 保留容器绝对图片链接和不匹配的概率相对链接；原字节不改。
   文档导航检查只排除本类原始报告，邻近 README 和项目文档仍校验；原报告及全部产物由证据 hash 检查覆盖。
