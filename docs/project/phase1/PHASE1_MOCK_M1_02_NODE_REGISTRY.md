## 1. 冻结结论

- 一期节点注册表严格包含 `N01`～`N18`，共 18 项。`node_id` 是一期业务主键，不能由 S 步骤、
  工具名、工作流名或旧 `P0-P7` 阶段名替代。
- 每个节点同时冻结一个 ASCII `node_key`，供后续契约、日志和测试稳定引用。`node_key` 只是
  本注册表内的语义键，不提前定义 M1-06 的 workflow/tool/scenario/run_id 命名空间。
- `display_name` 使用当前一期项目化名称；界面推荐显示为 ``{node_id} {display_name}``，但前缀
  拼接不是节点身份的一部分。
- 输入输出责任只描述节点应消费和应生产的**语义事实**。字段名、数据类型、必填性、数组结构、
  null 规则、ArtifactRef、错误和审计 envelope 全部由 `PH1-MOCK-M1-04` 定义。
- Gate、WT 直达分支、N12 重算控制、N16 条件和 N16/N17→N18 汇合均不是额外业务节点；其边、
  状态和终态由 `PH1-MOCK-M1-03` 定义。
- 本注册表描述目标职责，不代表任何科学工具、Agent C 接口或一期 Workflow 已部署；生产状态仍为
  `NOT_DEPLOYED`。

## 5. 单一责任与复用护栏

1. **WT 与候选结果分域**：N02、N04-N10 的主结果是 WT 基线；N13 的复跑结果是候选级事实，
   必须关联候选身份，不能覆盖 WT 生产者。
2. **同一 S 步骤可有不同节点责任**：S-31 的 BuildModel 候选模式属于 N14，WT/PositionScan
   模式属于 N17；共享实现不改变两个业务节点的身份。
3. **组装不是补算**：N18 只汇总、校验、披露和交接。上游缺失、失败、条件不适用或未执行时，
   N18 保留该事实，不调用科学工具补洞。
4. **Gate 不归 N10**：N10 只产 WT 可开发性事实。设计适用性 Gate 是后端控制判断，M1-03
   冻结其路由与状态；Dify 只消费固定结果。
5. **重算不归 N12 内部编排**：N12 负责给出本轮验证事实；是否回到 N11、当前轮次和停止条件
   由 M1-03 状态图定义。
6. **条件不等于删除**：N16 无表达宿主时仍保留节点身份；如何记录条件跳过由 M1-03/M1-04
   定义。未来 reduced profile 的物理削减仍受 OI-020 约束。
7. **LLM/Dify 不成为生产者**：科学计算、门控、Hard Filter、Pareto、校验和内部数据加工的
   权威生产者始终是 MCP/后端或科学 Worker；LLM/Dify 只收集、调用、等待、路由和解释事实。
