# BepiPred 验收清单

逐项记录 PASS / FAIL / NOT_RUN / BLOCKED，并附证据路径。
本页是待执行清单，所有用例初始均为 NOT_RUN；模型运行、解析测试和科学验收分别记录。

## 第一轮：原工具事实

| 编号 | 要做的检查 | 通过依据 |
|---|---|---|
| BP-01 | 安装与版本 | BepiPred 3.0 的实际 commit、依赖、help 和来源齐全 |
| BP-02 | 模型可用 | 所需模型/缓存均有身份、hash 和位置；实际调用可运行 |
| BP-03 | 真实参考样本初跑 | 原始 FASTA、CSV、命令、退出码及输入 hash 齐全；样本来源获确认 |
| BP-04 | 断网运行 | 记录隔离方式、网络观察；模型与依赖在本地，无临时下载依赖 |
| BP-05 | 输出事实 | 列名、位置基址、原始概率/滚动平均、阈值/Top 输出分别定位 |

包内 input.fasta 可以做工程 smoke，不能代替 BP-03 的科学参考样本。
第一次回传不要求同事自己裁决 BP-D02；把原工具事实交清楚即可。

## 第二轮：解析与错误

| 编号 | 场景 | 通过依据 |
|---|---|---|
| BP-06 | 完整性 | 每个输入位置恰有一个结果；序列 ID、残基字母、长度一致 |
| BP-07 | 坐标 | 明确原始基址，转为 1-based；首尾位置和内部位置都核对 |
| BP-08 | 数值 | 数值可解析且有限；缺行、重复行、NaN/Infinity、错列均能报错 |
| BP-09 | 版本防混用 | 不接受未经适配的其他大版本格式，不默默猜列 |
| BP-10 | 模型/命令失败 | 明确 failed；上层能按 S-17 halt，不伪装“没有表位” |
| BP-11 | 超时/取消 | 停止实际子进程，证据完整，不遗留推理进程 |
| BP-12 | 无原始分数 | 仅有分类 FASTA 时不能伪造 linear_scores，明确报错/缺证据 |
| BP-13 | 后处理未确认 | 保存原始产物，result=null、不可供主流程消费，不冒充无峰 |

scores.fixture.json 是任务内部的人工解析数据，不是官方 CSV 格式；
原始 CSV 解析必须另用实际版本的产物测试。

## 第三轮：确认规则后验证峰

BP-D02 由主开发协调算法负责人确认并记录版本，之后才能给下列用例写最终科学预期。
必须保留规则出处，不能根据自己实现生成“正确答案”。

| 编号 | 要覆盖的边界 | 验证要求 |
|---|---|---|
| BP-14 | 分数列/平滑 | 与确认的列与参数一致，原始分数仍可追溯 |
| BP-15 | 阈值比较 | 覆盖 0.1511999、0.1512、0.1512001；独立验证严格大于，不把边界因显示取整改变 |
| BP-16 | 长度 5/6/7 | 按已确认的有效长度/合并顺序检查，不产生偏一错误 |
| BP-17 | 间隔 0/1/2/3 | 包含短段被间隔连接的案例；不超出确认的桥接规则 |
| BP-18 | Top20% | 与确认消费方式及并列/取整规则一致；不改成前 20 个、不自行取 AND/OR |
| BP-19 | 峰起止和均值 | 首端/末端峰、单峰、多峰、桥接区均值分别验证 |
| BP-20 | 无峰 | 确认规则下无峰为合法成功，返回 []，同时保留全部分数 |
| BP-21 | 一期边界 | 只做 BepiPred；不调用 DiscoTope，不生成构象分数或 E2 共识 |
| BP-22 | 参数与追溯 | 非默认阈值有允许范围与 relaxation_metadata；记录 rule_profile |

具体待裁决输入见 rule_questions.json；其中 expected=null 表示尚无裁决，
不能把这些用例当成已经通过的测试，也不能从最终验收清单中删除。

## 第四轮：科学对照与交接

主开发协调提供有来源的真实序列和参考结果，覆盖普通输入、不同序列长度及可复核的有峰/无峰案例。
原工具与适配器使用同一模型/参数；原始分数对照和项目后处理规则分别验证。
算法验收人确认容差及结果，不能仅把新适配器的输出保存成 golden 文件后自证通过。

| 编号 | 检查 | 通过依据 |
|---|---|---|
| BP-23 | 原始分数对照 | 原工具实际输出与解析结果逐位相符；基址和列选择可检查 |
| BP-24 | 项目规则对照 | 使用已确认判定表与独立预期检查，差异有说明 |
| BP-25 | 干净环境复现 | 另一环境能按说明安装、找到本地模型并断网重跑 |
| BP-26 | 主开发接收 | 实现、证据和未完成项交齐，单工具结论回填 W2 准备记录 |

## 公共接口自查（CI-01～05）

下列同样是待执行的同事验收清单，不能用资料包的人工示例 PASS 替代适配器通过。

| 编号 | 需要交回的证据 |
|---|---|
| CI-01 | 使用 contract_version=0.1.0 的请求、结果，运行包内 validate.py 成对检查；不再输出旧草案字段 |
| CI-02 | 正常、失败、规则待确认与本工具适用的跳过分支；退出码和 result.json 状态符合公共表 |
| CI-03 | request/parameters/规则及产物 hash 可复算，--check-files 通过；改一个文件后能检出失败 |
| CI-04 | 新输出目录、重复目录拒绝、超时/取消停止子进程；不读旧结果、不覆盖其他执行 |
| CI-05 | 人工/G0 结果不能标为可供主流程消费；真实 pipeline 须有对应 G1、映射/规则和科学验收依据 |

从解压目录执行：

```bash
python interface/validate.py --examples
python interface/validate.py --request examples/request.example.json
python interface/validate.py --request delivery/request.json --result delivery/output/result.json --check-files
```

前两条可用本包资料检查，第三条的 delivery 文件需由你实际交付后执行。
退出码 0 只说明校验器所检查的工程范围通过；限制见 [公共接口](interface/README.md#7-校验能证明什么)。
