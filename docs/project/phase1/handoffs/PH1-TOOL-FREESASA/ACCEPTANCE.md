# FreeSASA 验收清单

逐项记录 PASS / FAIL / NOT_RUN / BLOCKED，并附输入、命令、结果文件及原因。
本页是待执行清单，所有用例初始均为 NOT_RUN；人工转换测试通过不代表真实工具或科学验收通过。

## 第一轮：原工具事实

| 编号 | 要做的检查 | 通过依据 |
|---|---|---|
| FS-01 | 安装与版本 | 目标环境可 import/调用，版本、安装来源和参数可追溯 |
| FS-02 | 真实 PDB 样本 | 原工具成功，逐残基绝对面积和输入 hash 有原始文件 |
| FS-03 | 断网运行 | 本地依赖齐全，运行期间不需下载或外部查询；附隔离方式及网络观察 |
| FS-04 | 失败样本 | 无效路径/损坏结构能明确失败，保留错误，不生成伪造结果 |

主开发提供样本或确认可用来源。人工 JSON 不能作为 FS-02 的证据。
第一轮回传后评审版本、映射、规则和接口；适用 G1 未通过前，不宣称适配器可供生产使用。

## 第二轮：转换和接口

| 编号 | 场景 | 明确预期 |
|---|---|---|
| FS-05 | A/R/G 参考表 | 使用 Theoretical 值 129/274/104；完整 20 残基表逐项核对 |
| FS-06 | 人工 SASA 转换 | 通过 conversion_cases.json 的单位、null、严格小于与分母检查 |
| FS-07 | 链与插入码 | 对主开发确认的映射逐位匹配；不同链同编号、42 与 42A 不混淆 |
| FS-08 | partial | 输出长度等于输入序列长度，缺失位置 null，后续位置不移动 |
| FS-09 | 映射过期/缺失/歧义 | hash 或映射状态异常可检测，阻止自动消费，问题可定位 |
| FS-10 | 非标准残基/不可算面积 | 按原件置 null+WARNING，具体问题进入复核；不得换成 G 或删位置 |
| FS-11 | N02 quality=low | 不执行本次 FreeSASA，返回 skipped 与原因，result=null |
| FS-12 | 非 low | 使用已确认参数执行，不以 topology_reliable 等其他字段擅自代替质量条件 |
| FS-13 | 解析格式 | PDB/CIF/mmCIF 分别标记原生支持、经评审转换或待集成；原件和映射可追溯 |
| FS-14 | 多链/MODEL/原子选项 | 与主开发确认的计算上下文一致，设置写入证据 |
| FS-15 | 超时/取消 | 子进程被停止，退出码/错误清楚，不遗留作业或读取旧结果 |
| FS-16 | RSA 出域 | 保留原始证据，未裁决前不可用于主流程，不静默裁剪或报正常 |

FS-13 的工具侧成果可以说明通过公共转换器完成；不得为“支持格式”复制一套未经审核的结构解析规则。

## 第三轮：科学对照和可复现交付

至少覆盖：完整单链、已核验 partial/插入码、多链上下文与相关格式转换的真实结构样本。
样本来源和可用范围由主开发协调确认，预期及容差由算法验收人确认。

参考结果应来自主开发提供的基线或经其确认的独立原工具调用与人工映射核查；
不能仅用同一新解析器生成预期又检查自己。SASA 与 RSA、结构对应关系应分别核验。

| 编号 | 检查 | 通过依据 |
|---|---|---|
| FS-17 | 数值与映射对照 | 同一结构/参数下对照参考结果；记录容差、差异及算法验收结论 |
| FS-18 | 干净环境复现 | 另一环境按运行说明安装并重跑，结果在约定容差内一致 |
| FS-19 | 交付完整性 | 源码、锁定依赖、本地包说明、样本/来源、测试、证据、未完成项齐全 |
| FS-20 | 主开发接收 | 工程接口评审通过，科学验收结果明确；回填 W1 对应任务 |

包内教学数据仅用于 FS-05/06 及解析边界练习，不用于以上真实结构验收。

## 遇到阻塞时怎样写

写清“哪个用例、输入文件/hash、命令、错误、已尝试内容、缺哪项具体依赖”。
例如：“FS-09：当前 mapping 对应的结构 hash 与本次文件不一致，需要主开发提供匹配版本。”
不要写“工具不好用”“需要更多资料”这种无法定位的问题。

## 最终交付目录建议

```text
delivery/
  README.md                 # 实际安装、运行、测试命令
  src/                      # 独立工具实现
  tests/                    # 单元测试和真实样本回归入口
  requirements.lock.txt     # 实测锁定版本
  assets_manifest.json      # 包/依赖/参数/数据的来源与 hash
  samples/                  # 可交付的输入；受控样本用引用说明
  evidence/                 # 原始输出、命令、日志、对照结果
  HANDOFF.md                # 填好的回传表和未完成项
```

上面是同事需要交付的目录结构，不表示本任务包已包含这些实现。

## 公共接口自查（CI-01～05）

下列同样是待执行的同事验收清单，不能用资料包的人工示例 PASS 替代适配器通过。

| 编号 | 需要交回的证据 |
|---|---|
| CI-01 | 使用 contract_version=0.1.0 的请求、结果，运行包内 validate.py 成对检查；不再输出旧草案字段 |
| CI-02 | 正常、失败、规则待确认与本工具适用的跳过分支；退出码和 result.json 状态符合公共表 |
| CI-03 | request/parameters/规则及产物 hash 可复算，--check-files 通过；改一个文件后能检出失败 |
| CI-04 | 新输出目录、重复目录拒绝、超时/取消停止子进程；不读旧结果、不覆盖其他执行 |
| CI-05 | 人工/G0 结果不能标为可供主流程消费；真实 pipeline 须有对应 G1、映射/规则和科学验收依据 |

从解压目录执行：

```bash
python interface/validate.py --examples
python interface/validate.py --request examples/request.example.json
python interface/validate.py --request delivery/request.json --result delivery/output/result.json --check-files
```

前两条可用本包资料检查，第三条的 delivery 文件需由你实际交付后执行。
退出码 0 只说明校验器所检查的工程范围通过；限制见 [公共接口](interface/README.md#7-校验能证明什么)。
