## 2. 推进任务

整体、阶段与当前交付包由用户指定的计划管理任务统一维护，职责与调整规则见 [交付计划](docs/project/PHASE1_DELIVERY_PLAN.md)。实施任务回填实际成果、验证和具体阻塞，管理任务据此校准下一项。

- **按交付包完成工作。** 在已授权范围内连续完成设计、实现、测试和普通补证，不因小项完成反复询问是否继续。
- **分别判断放行条件。** 开发接入、科学消费、目标发布按现行交付计划分别判断；未定科学分支保持关闭，无关依赖不阻断独立工作。
- **把阻塞限定到具体动作。** 记录缺什么、影响什么、关闭证据和主责，继续其余可执行工作；普通问题留在当前包内，不自动新增准备阶段。

遇到字段、格式、阈值、科学规则或工具行为问题，按以下顺序处理：

1. 从 [权威索引](工作流设计/01-业务依据/README.md)定位对应 ToolSpec、SOP、Schema、SKILL 或环境清单，只读适用章节，并核对最新用户决定。
2. 最新用户明确决定及原始附件优先；一期图决定范围、流程、优先级和削减顺序，当前专家包决定保留能力的科学细节。派生计划、契约、代码和测试不得反向改写原意。
3. 已有依据直接落实并保留来源文件、章节和版本；工程问题由工程处理，真实科学缺口交算法专家，范围取舍交用户。并列原件冲突须列明来源、范围、影响和建议，不猜阈值或接口，不把未完成检索变成宽泛问卷。

旧评审中的开发停止条件不覆盖最新用户决定；其历史执行结果和未签收事实仍按原时点保留。

## 3. 项目底线

**科学职责与资格**

- LLM 只收集输入、调用、等待和解释事实；Dify 只编排并按后端固定状态路由。科学计算、校验、门控、Hard Filter、Pareto 和内部数据处理由 MCP/后端执行。
- Mock 不得用于科研结论或生产候选。开发结果未签收前不得科研消费或自动交接；无真实部署证据保持 NOT_DEPLOYED，完整发布仍须满足适用 G0–G6。

**一期范围与离线运行**

- 默认交付 [范围基线](docs/project/PHASE1_SCOPE_REBASELINE.md)的完整 18 个业务节点；N03/S-03 只保留本地 BLAST、移除 IEDB 检索。原编号、设计 Gate、WT、重算、条件节点和最终交付保留，不静默削减。
- N01 接收序列、宿主物种和可选本地结构；无结构使用本地 AlphaFold3/ESMFold2。禁止 S-07/RCSB/AFDB 查询及联网回退，数据库能力使用批准的本地数据包。
- 当前一期使用独立 workflow/tool/scenario/run_id/template/bound 命名与运行资产；旧 P0–P7 Mock 和 S07 只作历史参考，不回流当前范围、实现或验收。

**原件、资产与操作**

- 用户与专家原件不得擅自删除、清空、覆盖或写回派生解释；冻结资产按 manifest 只读验证，不改后沿用旧 hash，不回写冻结时点声明。
- Mock DSL 遵循其唯一生成源；冻结源码不原地改作生产生成器，不修改或复用旧完整 Mock 的生成器和产物。具体路径查架构与运行手册。
- 密钥不得写入仓库、DSL、日志或文档；未经要求，不初始化 Git、不提交、不推送。
