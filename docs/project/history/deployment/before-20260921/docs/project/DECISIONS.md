## 统一常驻单卡 Worker

2026-09-20用户在确认当前账号不能创建Role/RoleBinding后，明确选择：“一个常驻 GPU Worker，只申请一张 A100 64GB，内部按顺序启动不同工具的计算进程。”该决定取代当天准备但未上线的动态GPU Deployment/专用RBAC方案，不要求再向管理员申请Role/RoleBinding。

## 首条工程链与 AF3 部署顺序

2026-09-18 用户在比较“先完整部署 AF3”与“先用 ESMFold2 跑通整个流程”后，确认采用后者。当前主线以一个明确、落在 ESMFold2 已验收工程支持域内的测试输入，收敛 N01–N18 首条工程链；结构预测显式使用 ESMFold2，不等待 AF3。

本决定中的“跑通”指真实输入进入统一运行层并最终到达 N18 报告/ZIP，各节点如实登记执行成功、跳过、失败或阻塞及其来源证据。它不要求通过修改 Gate、伪造候选或把跳过记作成功来形成全绿，也不表示科学 Gate、自动交接或生产状态放行。

AF3 仍属于一期范围，但当前并行工作只限于只读挂卷盘点、下载回执与归档身份复核、实际可用空间核算，以及安全解压清单/dry-run准备；保留现有权重、9份数据库归档、PVC和完成Job，不重新下载、不删除归档腾空间。首条工程链到达 N18 并形成稳定差距表后，再依次执行安全解压、完整文件清单核验、固定环境、本地数据搜索、权重加载、短样本5次推理和统一任务层接入。

当前 ESMFold2 常驻工程支持上限仍为76残基，393残基只是一条独立容量案例。若最终选定的首条输入超过现行支持域、又不能提供已登记本地结构，或业务明确要求 AF3 结果，则在启动该输入前重新评估结构路径并记录调整，不以容量单例静默扩大支持范围。

此决定只调整执行顺序，不取消双模型目标，不改变 N01–N18 范围、科学开放项、用户现场操作分工或最终生产门禁。实施顺序与完成证据见[交付计划](PHASE1_DELIVERY_PLAN.md#模型接入续行计划2026-09-17)。
