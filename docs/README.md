## 写文档的规则

- **按角色限制写入。** 负责代码和部署的 AI 只能写 [STATUS](project/STATUS.md)，其余项目文档只读；计划和其他文档由用户指定的计划管理任务维护。实施方将事实、证据及调整建议写入 STATUS，不自行改计划或另建替代计划。代码、测试、部署配置与实际运行证据按既有授权操作，完整边界见 [AGENTS](../AGENTS.md#2-推进任务)。以下文档整理要求由管理任务执行。
- STATUS 只保留当前能力、具体阻塞、下一项和最近验证摘要；历次过程放对应执行记录，不持续追加到首页。
- 同一交付包用一份任务页维护范围、完成标准、用法与必要问题清单；设计/准备/补证/修复默认是包内步骤。
- 当前任务与阶段入口直接链接到实际文件，不依赖跨文件的 `#章节` 跳转；尚未建立的文档只写待展开，不放空链接。文件内章节导航可保留，须验证标题存在。
- 文档检查覆盖普通链接、引用式链接和现行标题锚点。历史原文中的旧路径单独报告；现存目标从 [历史链接恢复入口](../legacy/README.md)查阅，不把静态检查通过等同于编辑器点击已验证。
- 能在既有任务页或代码中说明的内容不另建文档；新增文档须有独立且持续的查阅用途。
- 科学规则只引用权威来源，工程决定只写决定登记，执行产物与 hash 只维护对应机器证据；其他页面链接过去。
- 重要用户决定保留原话与适用范围；完成和冻结时的原始记录不回写。前序资料留在原位按主题查询，不作为接手必读清单。
- 一次变更更新适用页面并执行对应检查，不为文档整理再建立一套准备、评审和补证文档。

根 README 负责产品介绍，[AGENTS.md](../AGENTS.md)负责 AI 接手、推进和交付的工作约定，本页负责查找与维护规则。路线图仅导航，不复制第二份计划。

## 周期检查

计划管理任务定期核对：计划与代码/证据是否相符，当前入口与下一项是否一致，是否存在重复计划、过时现行口径、失效链接、无独立用途的新文档或过碎的准备步骤。优先检查现行入口和近期变动，有具体问题再追溯历史。
能直接核实的问题在既有页面修正；派生内容按唯一职责归并并检查引用，用户/专家原件及冻结证据保留。变化回填现有摘要，不为每次巡检新建报告；没有实质变化时不改写文档。周期设置由本管理任务在应用内维护。
