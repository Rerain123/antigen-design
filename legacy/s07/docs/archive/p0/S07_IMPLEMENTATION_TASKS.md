## 1. 这一步交付什么

S-07 接收本次运行已经保存的目标序列及已有检索辅助信息，取得可供后续分析的已有结构。
原文规定的正常路径为：

```text
目标序列
  → 查 PDB 实验结构，按原文筛选和选择
       → 取得结构：交给 S-09 评估质量
       → 无可用实验结构：查 AlphaFold DB
            → 缺 UniProt 编号：先用 BLAST 查 UniProt，再查 AlphaFold DB
            → 取得结构：交给 S-09
            → 规定的检索正常完成且均无结构：交给 S-08 预测
```

工程需要交付三类可区分的结果：

| 情况 | 后端交付 | 后续处理 |
|---|---|---|
| 已取得结构 | 结构文件引用、来源、方法、分辨率、覆盖情况、选择依据、警告和版本记录 | 进入 S-09；质量等级由 S-09 产生 |
| 正常检索完成，均无结构 | 结构为空，并保留各来源的查询结果 | 进入 S-08；不生成科学失败报告 |
| 检索没有正常完成 | 明确的错误、已完成部分和可恢复信息 | 按已确认的错误与恢复规则处理，不伪装成正常无命中 |

依据：[Agent A SOP] S-07 L218–234、T-01 L1880–1882；[结构链规格] §2a、§3、§5；
[既有开发决定] D03、D06–D10。候选、错误和产物的具体机器字段在 v0.6 契约中落定。

## 2. 直接采用与暂行规则

- PDB 搜索门槛为 **identity >95% 且 coverage >90%**；两个条件都要满足，等于阈值不通过。
  数值来源和换算方式已在任务 3 用锁定检索工具核验，不把坐标覆盖率混入该筛选。
- **S07-T3-P01，暂行/待专家确认**：coverage 使用输入序列的 query coverage；target coverage
  只记录、不参与 Hard Filter。
- 分辨率可比时，选择最小的正 Å 数值；例如 2.0 Å 优于 3.5 Å。
- **S07-T3-P02，暂行/待专家确认**：存在合格 X-ray/cryo-EM 时，取其中最小正 Å；没有可比
  候选时再进入 NMR 选择。多个 NMR 无法唯一选择时停止自动选择，不按数据库返回顺序打破平局。
- PDB 无可用结构后使用 AlphaFold DB。BLAST 的指定用途是查 **UniProt 编号**，再取得
  AlphaFold DB 结构。已有结构包含公共预测结构，不需要重新讨论它是否算“已有”。
- 对符合检索条件但只覆盖部分位置的结构，保留 `partial` 和缺失位置；后续逐残基计算在缺失
  位置留空并警告。原文没有规定“坐标不全就一律丢弃”，本任务不增加此类门槛。
- `source=none` 仅用于 S-07 内部；最终结构对象为空时，不向 CandidateRecord 写入非法的
  `source='none'`。S-07 不为满足最终 Schema 提前编造质量等级。
- 当前 P0 按专家环境清单使用 RCSB、UniProt 和 AlphaFold DB API 完成查询链、契约与验收取证。
  D09 的服务器本地、不可修改版本化数据仅约束最终目标服务器的本地化部署；该部署由对方部署
  团队执行，不是用户工作站上的前置任务。无论 API 或本地 profile，完整轻量候选自动取得，
  结构大文件按筛选结果读取；候选去重与文件去重分开。

依据：[Agent A SOP] L223–233；[结构链规格] L25–29、L57；[Agent A Schema] L104–120；
[既有开发决定] D09。原始资料版本与哈希见 [P0 来源快照](../../../../project-history/p0/P0_EXPERT_EVIDENCE_SOURCES_20260902.json)。

| D09–D10：数据、去重和错误 | 当前 P0 走专家环境清单的 API；D09 本地版本化数据只用于最终目标服务器 profile，由对方部署团队执行；两者保持同一结果/错误契约 |
| D11：三类命中的分类体系 | 属于旧 discovery 暂定模型；专家 S-07 未要求先建立该分类体系，不作为当前任务前置审批 |
| D12–D13：合格结构、结构选择 | 严格阈值、可比最小分辨率及 partial 直接采用；剩余不可比/并列/多链情况放进任务 3 的具体候选核验 |
| D14：来源顺序 | PDB→AlphaFold DB，以及缺编号时 BLAST→UniProt 已明确，按任务 3、4 实施 |
| D15–D16：编号映射和 BLAST | 用途和目标库已明确；数据版本、实际输出与一对多编号情况由任务 2、4 取证 |
| D17：输入边界 | 已有长度守卫直接采用；具体工具字符支持和解析问题先用工具资料/实测处理，不追加分析模式问题 |
| D18：运行配置 | 耗时、并发、重试、文件保留的实施档案由工程依据实测准备；不把每个配置项都交给用户定数字 |

以上是依据归类和任务分配，不代表 OI-018 已关闭，也不改写旧观察报告中的历史事实。

## 6. 需要继续查证的点和提交方式

任务 3 已把检索输出的覆盖率口径和跨 NMR 方法选择收敛为两项带实际影响数据的规则；用户
已批准按建议方案暂行，专家确认仍保持 `PENDING`。多链无法唯一选择已经由 R-58 直接处理。
任务 4 又以官方 API 完成一对多编号、accession 无 AFDB 模型、标识非法、序列不符和正常
空结果取证，不扩成全 P0 的用户问卷。

先查询工具资料并保存实际输入/输出，判断能否按专家现有规则直接处理。若多种处理会产生不同
结构选择，且现有资料不能决定，才整理“遇到什么情况—原文各怎么写—会影响什么—建议怎样改”
的确认记录；未明确的科学处理不以软件默认值补齐。真正相互冲突与尚未展开的规则分别注明。

任务 4 证明原文仍不能唯一决定三点：非精确 BLAST accession 的使用门槛、多个合格 accession/
model 的选择顺序，以及 Swiss-Prot 或整个 UniProtKB 的搜索范围。具体实测影响和五项统一建议见
[专家确认问题总表](S07_EXPERT_CONFIRMATIONS.md)。五项均已获用户批准作为暂行工程方案；专家
结论前不把它们标记为正式科学规则。最终目标
服务器本地发布由对方部署团队按交接清单执行，不是当前 P0 API 取证的前置项。
