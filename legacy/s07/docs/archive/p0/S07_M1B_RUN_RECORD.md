## 2. 最终批次结果

- 共执行 57 次来源调用：41 次 HTTP 成功、2 次 RCSB 正常空结果、1 次 AlphaFold DB 明确返回
  不支持的标识、13 次本地 CLI 成功。
- 执行层失败 0 次；57 条调用记录均通过完整性检查；HTTP 和 CLI 的 stderr 均为空。
- 审计清单统计 285 个非报告文件、23 类文件，共 12,030,181 字节，约 11.5 MiB；每个文件都有
  SHA-256。
- RCSB 5 个查询共 19 页。三个有结果的查询分别完整取得 1136、236 和 125 个 polymer entity；
  两个无结果查询均以 HTTP 204 正常结束，没有被记作故障。
- 上述三个结果集分别对应 1004、235 和 103 个 PDB entry；同一 entry 内多出的 entity 数分别为
  132、1 和 22，证明 entry 与 entity 不能用同一个身份层级表示。
- 4 个冻结观察对象产生 16 个 RCSB 响应正文，合计约 8.0 MiB。这里的对象只用于观察
  entry/entity/chain/mmCIF 输出组成，不表示工具选中了这些结构。
- AlphaFold DB 对两个明确的 UniProt accession 各产生元数据、CIF、置信度和 PAE；RefSeq
  `WP_505187596.1` 得到 HTTP 400，说明它不能直接作为该接口的合法标识。
- 4 个 BLAST 样本均产生 `.asn`、`.tsv` 和 `.json`。前三个样本都达到 discovery profile 的
  100 条上限，第四个返回 42 条；该上限仍不是生产规则。
- 发现 19 组非空字节重复文件，全部是“分页请求原件”与“exchange 内保存的请求副本”成对重复。
  这说明正式快照需要确定唯一保存位置或引用关系，但本次不直接替 D09 作决定。

## 3. 为什么有四个批次

原始证据从不覆盖。发现采集问题后使用新批次修复并重跑，因此保留以下记录：

| 批次 | 结果 | 发现的问题 | 用途 |
|---|---|---|---|
| `p0-s07-m1b-20260901-a` | 29 次调用，5 次 CLI 失败 | curl 全量 JSON 在 Windows 中文路径下无法可靠解析状态；BLAST LMDB 不能打开中文数据库路径 | 失败证据，非最终审计 |
| `p0-s07-m1b-20260901-b` | 在线查询完整，5 次 CLI 失败 | 状态解析已修复；执行器又把临时 ASCII 盘符解析回中文真实路径 | 失败证据，非最终审计 |
| `p0-s07-m1b-20260901-c` | 57 次调用全部成功 | curl 写出一个不支持的版本字段，产生 44 个相同警告文件，污染重复统计 | 成功但有采集器噪声，非最终审计 |
| `p0-s07-m1b-20260901-d` | 57 次调用全部成功 | 无执行失败、无非空 stderr、临时盘符已移除 | **最终审计批次** |

前三个批次保留是为了证明问题如何暴露和修复；不得把它们与最终 D 批次拼接成一份结果。

## 4. P0-M1B 当时未决定、后续已确认什么

P0-M1B 完成时只表示 S07-D09 的重新评审条件已经满足，当时尚未确认以下事项：

1. 主结果与结果文件引用的边界；
2. entry、entity、chain、model、assembly 各自的身份键和去重范围；
3. 查询快照需要保存的请求、分页、来源时间、工具/数据库版本与哈希；
4. 正式分页接口，以及审计保护上限与生产限制的分离方式。

wing（开发者）已于 2026-09-02 根据这些证据确认 D09：后端自动取得完整轻量候选、重型结构按需
读取；候选与文件分别去重；生产只使用服务器本地、不可修改的版本化数据库；文件按运行说明、
原始科学数据、整理中间结果、最终结果、日志/临时文件分类并执行差异化保留。详细决定见
[S-07 契约评审稿第 9 节](S07_CONTRACT_REVIEW.md)。

S07-D11 至 D17 仍等待算法/产品负责人确认，因此 D09 完成评审不能单独解除 P0-M2 的全部门禁。

## 5. 复现入口

Windows 中文工作区使用包装脚本；它会检查临时盘符未被占用，并在运行结束后自动移除：

```powershell
.\scripts\run-p0-s07-m1b-windows.ps1 -CampaignId p0-s07-m1b-<new-id>
```

已有批次只需重新生成报告时，不访问远端来源：

```powershell
.\.venv\Scripts\python.exe .\scripts\build_p0_s07_m1b_audit.py `
  --campaign-root .\discovery\p0\s07\p0-s07-m1b-<id>
```

每次新运行必须使用新的 campaign ID；执行器会拒绝覆盖非空批次目录。
