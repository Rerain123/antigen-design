## 1. 已确认的实施顺序

真实化严格按照 T-01 v10 的阶段顺序推进：

```text
阶段0工具与发布包 -> 阶段0工作流与回归 -> 冻结 P0
  -> 阶段1工具与发布包 -> 阶段1工作流与回归 -> 冻结 P1
  -> ...
  -> 阶段7工具/组装与发布包 -> 阶段7工作流与回归 -> 冻结 P7
  -> Master 全链真实回归
```

在阶段 N 的工具、发布包、阶段工作流和验收证据全部完成前，不开始阶段 N+1 的真实工具实现。
后续阶段可以提前收集许可证、硬件和负责人信息，但不能绕过阶段门禁写入生产路径或宣称部署完成。

## 2. “阶段工具打包”的含义

阶段发布包是一个可部署、可复现、可回滚的 release bundle，不要求把所有工具塞进一个容器。
CPU、GPU、数据库型或许可证隔离的工具可以使用不同镜像/运行环境，由阶段发布清单统一引用。

每个阶段发布包至少包含：

1. 阶段号、工作流版本、包含的 MCP tool name 和明确排除项。
2. 每个工具的固定版本/提交、模型或数据库版本及 SHA-256。
3. 容器镜像摘要或等价的不可变运行环境；安装、预检、验证和回滚方式。
4. 输入/输出 Schema、ArtifactRef、错误分类、Provenance 和资源限制。
5. 同步/异步 execution profile；长任务必须符合 OI-017。
6. 许可证、使用范围、第三方依赖清单和必要的授权证据；不在仓库记录密钥。
7. smoke 样例、失败样例、算法负责人批准的金标准及机器可读比对结果。
8. 阶段工作流所引用的准确工具版本和发布包摘要。

`smoke` 只证明可调用；没有金标准和负责人证据，不能标记为生产科学能力。

## 3. 每个阶段的统一 Stage Gate

每个 P0-P7 阶段都依次经过以下门禁：

| 门禁 | 必须完成的内容 | 允许的阶段状态 |
|---|---|---|
| G0 工具摸底 | 在隔离环境运行冻结候选版本，保存原始输出、产物、错误、资源与版本证据；不接 Dify、不形成科研结论 | `DISCOVERY_EVIDENCE_READY` |
| G1 契约就绪 | 基于 G0 实测核对 v10 节点、输入输出、门控、错误和复用关系；受影响 OI 已 `DECIDED` 或明确排除在本阶段外 | `CONTRACT_READY` |
| G2 工具实现 | 按节点顺序实现适配器和纯后端计算；固定版本、参数、模型、数据库和 execution profile | `TOOLS_IMPLEMENTED` |
| G3 工具打包 | 形成阶段 release bundle；完成预检、安装、smoke、金标准、失败样例、许可证和回滚验证 | `TOOLS_PACKAGED` |
| G4 工作流实现 | 只修改 DSL 生成源；阶段 Workflow 使用已打包工具并保留确定性路由 | `WORKFLOW_READY` |
| G5 阶段验收 | 工具级、契约、阶段 Dify、故障与恢复回归全部通过；生成唯一批次证据 | `WORKFLOW_VERIFIED` |
| G6 阶段冻结 | 更新状态、运行手册、版本和基线；确认没有把 Mock/smoke 当生产结果 | `FROZEN` |

只有 `FROZEN` 才允许进入下一阶段。G0 输出只能标记为 `discovery`，不能作为已部署能力或
科研结论；工具在 G3 前不能写成 `DEPLOYED`，阶段在 G6 前不能写成“已完成”。

### 3.1 一期落地优先级与削减控制

阶段顺序回答“依赖上先做什么”，新基线的颜色回答“资源受限时哪些能力必须、受保护或可削减”。
二者不能互相替代：绿色节点不能绕过前序 Stage Gate，黄色节点也不能因排期靠后被静默删除。

- 必须：节点 1/2/3/4/5/6/8/9/11/12/13/15/18；节点 2 中 S-04 必须，S-11 单独属于削减池；
- 保留且受保护：节点 10、14、17，可后置实施，但不参与削减顺序；
- 削减池：节点 16 S-30 → 节点 7 S-12 → 节点 2 中 S-11，只能按此顺序显式裁剪。

当前没有触发削减，默认计划仍为完整一期。每个 reduced profile 都必须先关闭 OI-020，获得具名
批准，写明 profile ID、缺失能力、节点 13/下游降级、阶段解锁与回归范围。未批准的削减不能用于
赶进度，也不能用 `null`、工具失败或普通条件跳过伪装。

  -> 是否提供且可解析的结构？

### 5.1 P0 G0：先观察真实工具

现有 OI 首轮评审只作为风险和未知项清单，不作为科学 Schema 已定稿的证据。先由 V07-M1
按专家资料归并必填序列、宿主物种和可选结构；随后按 AlphaFold3/ESMFold2→S-09 规则事实→
DeepTMHMM→条件 FreeSASA 准备和执行 G0。S-07 与任何联网数据库不进入 G0；甲方服务器上的
AF3/ESMFold2 不受该网络限制。

每个工具至少用正常、边界和预期失败输入记录：

- 精确工具/模型/离线权重版本、安装方式、许可证和运行环境。
- 原始请求、标准输出、标准错误、退出码、原始文件/目录结构及 SHA-256。
- 实际字段、类型、单位、坐标系、枚举、缺失值、警告、失败和部分成功形态。
- 同一输入重复运行的确定性、随机种子行为，以及墙钟、CPU/GPU、内存、磁盘和网络需求。
- 哪些 v10 所需信息由工具直接提供，哪些需要无损解析，哪些根本不提供。

G0 不做项目阈值、PASS/FAIL、降级或业务路由的最终决定。工具实测决定“它事实上输出什么”，
算法/业务负责人再决定“项目如何解释和使用这些事实”。工具没有提供的信息不得由 LLM、Dify
或适配器猜造。

### 5.2 基于实测的 P0 契约审计

取得对应工具的 G0 证据后，再形成 P0 专用契约/实施清单并逐项核对：

- 专家资料定义的 `protein_sequence`、`host_species`、可选结构、PDB/CIF/mmCIF、chain 与 R-58，
  以及工程侧的 ArtifactRef、校验、哈希、来源、驳回、补交、替换和幂等；
- S-08 的 AlphaFold3/ESMFold2 路由、失败回退、输入限制、随机种子、离线模型版本和资源档案。
- S-09 的 method/resolution/pLDDT/pTM 输入来源，以及 high/medium/low 的边界冲突、缺失值和掩码规则。
- S-04 的 DeepTMHMM 标签/区段与派生量、P/B 降级、模型版本和部署许可；`is_membrane` 属下游消费。
- S-11 的链选择、R-58 序列映射、RSA 定义、缺失残基与错误/降级规则；先解除 OI-015 对
  S-11 的阻塞。
- S-07/RCSB/AlphaFold DB/BLAST-UniProt 回退和 S-06/PSORTb 均已排除；旧引用只作历史证据，
  不进入本阶段契约或发布包。S-11 当前默认保留；缩减语义由 OI-020 承接。
- S-08 等长任务按 OI-017 实现只读状态查询、deadline、取消、结果读取和恢复。

若现有 v10/数据契约未给出上述任一科学规则，应把 G0 原始证据附到新增或扩展的 OI，等待
相应负责人确认；不得使用行业惯例、工具默认值或 Mock 值填空。工具实测本身不能替代项目
阈值、门控和业务语义的权威决定。

### 5.3 P0 交付顺序

1. `P0-V07-M1` 从专家原文归并已确认输入、结构格式、校验、来源、驳回、补交、替换与幂等，
   关闭 OI-023；不把已有规则回问用户，不使用 accession 或网络补齐缺失输入。
2. 对 AlphaFold3/ESMFold2 执行内网等价 G0，固定离线镜像、权重、许可、GPU、原始输出、
   失败与资源事实；运行时不得访问公网。
3. 完成 S-09 Q08/Q09 决策与验证、DeepTMHMM G0，以及 OI-015/R-58 决定和 FreeSASA G0。
4. 汇总输入、状态/错误、ArtifactRef、P0EvidenceBundle 和 execution profile，达到 G1。
5. 实现 OI-017 状态机及 S-08/S-09/S-04/S-11 生产适配器，完成单测和金标准验收。
6. 形成可离线安装的 P0 发布包，验证预检、安装、smoke、断网、失败样例、许可和回滚。
7. 只修改 `src/t01_dify_workflows/generator.py` 生成 P0 v0.7 真实工作流，生产路径移除 S-07。
8. 重新生成、绑定、导入、发布 P0，并刷新其 Workflow Tool；旧 Mock v0.1 不覆盖。
9. 执行 P0 独立场景、断网、故障/异步恢复和受影响 Master 前缀回归，使用新唯一 run_id。
10. 更新状态、运行手册和基线，将阶段标记为 `FROZEN`，然后才开始 P1。

## 6. 最终全链验收

P0-P7 均冻结后，才启用 Master 的完整真实执行候选路径。最终至少需要：

- P0-P7 各自冻结的 release bundle 和阶段回归证据。
- Master 全链真实运行、降级/跳过/失败/取消/恢复路径和唯一 run_id 证据。
- 所有输出明确标注 `execution_mode`，Mock、smoke、production 结果不可混用。
- 版本、输入哈希、模型/数据库、参数、产物和交付边界可追溯。
- context 注入、S-23、S-32 等明确移出一期的能力保持不可调用并在交付中披露；S-44 属必须节点，
  OI-013 未解除前 P7 不能冻结，也不得用 `delivered=false` 冒充真实交付完成。
