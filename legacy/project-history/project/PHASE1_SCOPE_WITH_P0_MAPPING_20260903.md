### 1.1 节点 01 内网修订（2026-09-03）

甲方生产环境只有内网，不能依赖互联网数据库检索。节点 01 因此采用以下当前边界：

- 删除 RCSB PDB 与 AlphaFold DB 搜索；
- 节点 01 的科学工具只保留 AlphaFold3 与 ESMFold2；两者部署在甲方服务器，内网条件不影响正常使用；
- S-07 自动已有结构检索链不进入一期；其 BLAST→UniProt→AFDB 等辅助检索也不得从侧路恢复；
- 输入固定为目标蛋白序列、宿主物种和可选结构；有合法结构时先解析并进入质量评估，无结构时
  进入 AlphaFold3/ESMFold2 预测；
- 字段名、结构格式、校验、映射和失败规则优先从专家 SOP、Schema 与 ToolSpec 提取。OI-023
  负责工程归并与复核，不再把已有文档口径作为笼统问题回问用户；仅在原件出现具体冲突或真实
  缺口时提交相应专家。

## 4. 已确认的节点 13 与节点 15 高层规则

### 4.1 节点 13：表位保护验证

- L1：检查变体是否改变任何 WT 热点残基；
- L2：对热点区间与 E4 残基位置集合重算 RSA，平均 `variant - WT > -0.15`；
- L3：验证区间局部 Cα RMSD 和功能域局部 RMSD 均 `<2.0 Å`；shape similarity 只展示证据；
- L4：重跑 BepiPred/NetMHCpan/NetMHCIIpan 与 S-19，画像差 `<0.2`；成本保护为前 20 池；
- 同步复评变体可开发性五维；S-12 在该 release profile 包含时执行糖基化位点复扫；
- 一期不执行 S-23，交付必须披露“变体安全复评一期未评估”。

这些是当前高层科学/产品口径。验证区间坐标、RSA 聚合、RMSD 原子选择与对齐、画像差公式、
前 20 池产生时点、失败的 Hard/Soft 语义以及 S-11/S-12 被削减时的状态，仍须形成版本化契约。

### 4.2 节点 15：综合排序

- Hard Filter 剔除表位破坏、突变负担超档和用户显式覆盖的禁止候选；一期不执行安全与宿主同源项；
- Pareto 使用可开发性、稳定性、表位保持、突变计数四维；
- `general` 档权重为 `0.50/0.10/0.30/0.10`，表位软约束罚分 `-0.10`；宿主相似罚分一期不触发；
- 家族轮转配额 `<=5`，随后按序列 `identity>95%` 聚类，输出 top20；
- 最优候选可开发性综合分 `<0.30` 时降级为 WT 交接并记录风险，不给出绝对效果判断。

突变负担六维、各维归一化、稳定性 sigmoid、表位保持分、设计家族、聚类代表与并列顺序、非
`general` 目标档案和 SC-10 的 FailureReport 载体仍由既有 OI-008/OI-009/OI-010 与 OI-022 收敛。

## 5. 削减顺序与 release profile

默认计划继续建设包含 S-11、S-12 和条件 S-30 的完整一期基线。只有用户/产品负责人明确触发
进度削减时，才按以下唯一顺序处理：

```text
节点 16 S-30
  -> 节点 07 S-12
  -> 节点 02 中的 S-11
```

节点 10、14、17 受 D-06/D-07 保护，不进入削减顺序。每次削减必须产生新的 profile ID，并在
manifest、Schema、状态、回归和交付报告中列出缺失能力、空值原因、下游禁用/降级和恢复方式。
不得用工具故障、普通跳过或 `null` 冒充“计划削减”。

以下依赖尚未由新图完整定义，统一由 OI-020 承接：

1. 删除 S-11 后，节点 13 L2 是禁用、降级，还是保留独立 FreeSASA 能力；
2. 删除 S-12 后，节点 13 的糖基化复扫及相关 Hard/Soft 规则如何变化；
3. 不同削减层级能否称为完整一期/P0、正式命名和阶段解锁条件；
4. 当前项目何时满足“进度紧张”的触发条件、由谁批准以及是否允许后续补回。

OI-020 未决定前，当前 P0 v0.7 仍按包含 S-11 的完整四步骤推进，不因“削减池”三个字跳过
S-11 G0、OI-015 或验收。若以后批准无 S-11 的 P0 profile 解锁 P1，须再次升版并重新评审
G6 定义。
