当前没有 PSORTb 版本、许可、正常/边界/失败样本、Gram 模型或真实 G0 证据，也没有 A10 独立
ToolSpec。把 S-06 纳入会新增条件输入 `pathogen_type/gram_type`、

### 必须覆盖的边界案例

## 3. D-02：S-11 削减后能否称为完整 P0

### 原文出处与冲突

支持 S-11 属于一期完整基础分析：

- 一期边界 PDF 第 2 页“结构与基础分析”明确列 FreeSASA；第 4 页将其定义为节点 02 表面暴露
  计算；附加流程图将节点 02 映射为 S-04/S-11；第 10 页要求交付结构来源/质量、膜内外位置和
  表面暴露程度，并披露缺失与风险。
- T-01 算法图 L19–22、L247/L265 与 Agent A SOP T-01 L1884–1892 均保留 S-11：结构非 low
  时执行，low 时 rsa=null。

支持可削减：

- [FreeSASA ToolSpec](../../../工作流设计/01-业务依据/抗原智能体_v10.5_修订版_20260902/ToolSpec_C34_FreeSASA_v10.5.md)
  L4 写“削减池节点……默认实施”；
- 一期环境清单 L30/L34 将节点 2 的 S-11 列入削减顺序，但没有定义削减后版本名或验收口径。

### 现有实测/工程影响

S-11 尚未进行 FreeSASA G0，OI-015/R-58 仍阻塞。删除 S-11 会使 P0 缺少逐残基 RSA、
buried_fraction 和表面暴露证据；S-16 core_map、S-39 tag exposure、S-31/R-41 等后续消费者只能
得到 null/跳过或另行降级。保留 S-11 则需要完成 R-58、FreeSASA 参数/许可/版本、G0、Schema 和
发布验收。该批次当时没有证据授权把“因进度削减”写成与五步骤完整 P0 等价。

### 历史暂行建议

1. 当时的“完整 P0”定义为 S-07/S-08/S-09/S-04/S-11 五步骤；S-11 按 confidence 门控，low 时
   合法跳过不等于从 release 删除。
2. 允许另建不含 S-11 的缩减候选，但必须使用明确名称（讨论占位如 `P0_REDUCED_NO_S11`，最终
   名称由产品/专家确认），在 manifest、输出和报告中披露 RSA 不可用及下游影响。
3. 缩减候选不能通过“完整 P0”G6；应有自己的验收范围和对外能力声明。

### 可选替代规则

1. S-11 不可削减：没有 R-58/FreeSASA 就不能冻结任何 P0 release。
2. S-11 可从一期最小交付删除，且仍称完整 P0；须正式改写 PDF 节点 02、输出承诺和下游门控。
3. 同时定义 full/reduced 两个 profile；须明确默认 profile、版本名、升级条件和分别的 G1～G6。
4. 把 S-11 延后到指定阶段；须明确 P0 输出字段、后续回填/重算和兼容迁移。

### 必须覆盖的边界案例

- S-11 被打包但因 confidence=low 对单个 run 合法跳过；
- S-11 工具未打包、未授权、运行失败或 R-58 强制复核；这些状态不能都写成 rsa=null；
- full 与 reduced 输出 Schema 是否相同，如何表达 capability unavailable；
- 后续 S-16/S-39/S-31 消费 RSA 时的 null/跳过/失败；
- reduced 发布后补上 S-11 时是否为兼容升级或新 major profile；
- 对外材料能否使用“表面暴露分析完成”以及缺失披露措辞。
