## 1. P0 阶段到底在做什么

P0 是整个 T-01 流程的地基。后续要分析表位、判断哪些位置可以修改、设计新序列，都需要先知道
目标蛋白大致是什么形状、这份结构有多可信、哪些区域位于膜内、哪些残基暴露在表面。

可以先把当前 P0 的四个步骤记成四个问题：

| 步骤 | 它回答的核心问题 |
|---|---|
| S-08 结构预测 | 甲方未提供结构时，能否根据蛋白序列计算出一个结构模型？ |
| S-09 结构质量评估 | 当前结构有多可信，后续可以在多大程度上依赖它？ |
| S-04 拓扑预测 | 这个蛋白是否穿过细胞膜，哪些区段位于膜内或膜外？ |
| S-11 溶剂可及面积 | 结构中的每个残基更接近表面还是埋在内部？ |

它们在主流程中的关系是：

```text
甲方提供目标蛋白序列 + 宿主物种 + 结构（可选）
  -> 输入校验、结构解析与哈希
  -> 是否提供且可解析的结构？
       ├─ 是：使用甲方结构
       └─ 否：S-08 AlphaFold3/ESMFold2 结构预测
  -> S-09 结构质量评估
  -> S-04 拓扑预测
  -> 结构不是 low 时执行 S-11
  -> 形成 P0 基础证据包
```

这里的“一个工具”是业务上的一个步骤，不一定只对应一个软件。S-08 保留 AlphaFold3 和
ESMFold2 两个科学工具；S-09 则主要读取预测结果并按确认的规则作出分档。

## 2. S-07：结构获取（已移出一期）

> 2026-09-03 会议决定：甲方只有内网，节点 01 不再查询 RCSB PDB 或 AlphaFold DB，S-07
> 以及 BLAST→UniProt→AFDB 回退退出一期。以下内容只解释历史方案和既有 discovery 证据。

### 它解决什么问题

S-07 负责在重新预测结构之前，先检查外部是否已经存在可用结构。已有的实验结构通常包含真实
实验信息，公共预测库也可能已经计算过相同蛋白，因此不能一开始就重复运行昂贵的结构预测。

### 它怎样工作

S-07 以用户提交的蛋白序列为唯一依据。根据最终确认的检索方案，它可能使用：

- RCSB PDB：寻找公开的实验结构；
- AlphaFold DB：寻找已经公开的预测结构；
- BLAST：寻找相似蛋白，并继续判断其结构能否作为参考模板。

数据库返回的“命中”还不是可直接使用的结构。S-07 需要继续弄清楚命中对应哪个蛋白实体、哪条
链、哪个模型和哪种组装方式，还要核对目标序列与结构坐标真正对应了多少残基。截短体、突变体、
带标签的构建体和相似蛋白不能因为出现在搜索结果中，就自动当成目标蛋白的完整结构。

正式工具最终应给出两类清楚的结果：找到并选中了合格的已有结构，或者检索正常完成但没有合格
结构。查询失败、网络中断和数据库不可用不能伪装成“没有结构”。

### 为什么它可能产生很多数据

同一个蛋白可能因为不同实验条件、突变、配体、链和组装方式而对应大量 PDB 记录。本次 P0-M1B
实测中，一个 RCSB 查询返回了 1136 个蛋白实体，对应 1004 个 PDB 条目。

此外，S-07 还需要保存候选清单、分页响应、序列比对、残基坐标映射、结构文件、来源时间和文件
校验信息。P0-M1B 看到的 285 个文件是多个公开样本组成的完整审计批次，不是一次普通调用必然
产生 285 个文件；其中 4 个代表性 RCSB 坐标文件已经占约 7.6 MiB，也没有为全部 1136 个命中
下载结构文件。

正式版本的主结果应该保持简洁，大型原始数据和完整候选保存在后端，通过文件引用按需读取。

### 它不负责什么

- 不重新预测一个全新结构；这是 S-08 的工作。
- 不把结构评为 high、medium 或 low；这是 S-09 的工作。
- 不自行发明相似度、覆盖率或来源优先级。
- 不把“搜到结果”直接解释为“结构可以使用”。

### 当前项目状态

P0-M1 discovery 和 P0-M1B 输出审计已经完成。D09 曾确认自动取得轻量候选、分层去重、服务器
本地版本化数据库、文件分类和保留边界。三类命中的最终定义、结构可用标准、链与组装选择、来源
优先级、AlphaFold DB 映射和 BLAST 规则随 OI-018 转为 `DEFERRED`。S-07 不进入一期生产编码、
部署或当前专家外发任务；未来恢复时才重新评审这些问题。

## 3. S-08：结构预测

### 它解决什么问题

S-08 在甲方没有提供合法结构时，根据通过校验的蛋白序列计算三维结构模型。数据库检索移除后，它是节点 01 的
首个科学步骤，不再是 S-07 无命中后的补救路径。

### 它怎样工作

结构预测模型会分析氨基酸序列之间的关系，估计蛋白质折叠后各个原子或残基在三维空间中的位置。
当前计划是：

- 在甲方内网等价环境对 AlphaFold3 和 ESMFold2 做 G0，固定离线镜像、模型权重、许可和硬件；
- 生产运行不得临时访问公网下载权重、模板或数据库；
- AlphaFold 3 与 ESMFold2 的最终生产路由仍需确认。

这类任务通常耗时较长、消耗 GPU 显存，也可能因为序列过长、资源不足或任务中断而失败，因此正式
工具需要支持任务提交、进度查询、取消和结果恢复，而不是要求一次请求一直等待到底。

### 它会产生什么数据

主要数据包括：

- 三维坐标文件，也就是预测得到的结构模型；
- 每个残基的可信度信息，例如 pLDDT；
- 不同区域相对位置的不确定性信息，例如 PAE；
- 模型版本、参数、运行时间、随机种子和硬件环境；
- 如果生成多个候选模型，还会有各模型的排名和选择记录。

坐标和置信度文件可能比较大。AlphaFold 3 还可能产生数据处理过程文件和多个候选模型，正式版本
需要决定哪些必须长期保存，哪些只作为临时产物。

### 它不负责什么

- 预测完成不等于结构一定正确。
- 不负责把结果评成 high、medium 或 low；需要交给 S-09。
- 不负责判断蛋白是否跨膜，也不计算残基是否暴露在表面。
- 不能因为模型成功运行，就省略版本、参数和置信度证据。

### 当前项目状态

S-08 尚未开始真实实现。内网只排除外部数据库查询，不影响把 AlphaFold3/ESMFold2 部署在甲方
服务器使用。当前下一步先通过 OI-023 从专家资料归并输入契约，再执行两种模型的内网 G0；
在版本、权重、许可与运行证据完成前仍不能标记为 `DEPLOYED`。

## 4. S-09：结构质量评估

### 它解决什么问题

取得甲方提供结构或 S-08 预测结构以后，后续步骤还需要知道这份结构有多可靠。S-09 把结构的原始质量事实
整理成统一的 high、medium 或 low 分档，供后续流程决定哪些结构计算可以继续、哪些结论需要降级。

### 它怎样工作

实验结构和预测结构的质量证据并不相同：

- 实验结构通常关注实验方法、分辨率、坐标覆盖、R-work 和 R-free 等事实；
- 预测结构通常关注模型自己提供的 pLDDT、PAE、pTM 等置信度信息。

S-09 不让语言模型凭感觉判断，而是读取已保存的原始事实，再按照算法负责人批准并带版本的规则
生成分档。同一套规则必须能够重复运行并得到相同结果。

### 为什么它重要

如果把低可信结构当成高可信结构，后面的表面暴露、结构表位和设计结果都会建立在错误坐标上。
反过来，如果把可信结构错误降级，流程会跳过本来可以完成的结构分析。

在当前 P0 路径中，结构被评为 low 时会跳过 S-11，并明确记录没有 RSA 结果及其原因。

### 它不负责什么

- 不生成结构，也不修复结构中的缺失残基。
- 不把所有来源的数字强行当成同一种指标。
- 不能把实验结构中的 B-factor 在没有证据时直接解释成预测结构的 pLDDT。
- 不判断残基位于表面还是内部；这是 S-11 根据坐标计算的结果。

### 当前项目状态

S-09 尚未开始实现。v10 给出了 high、medium、low 的业务要求，但实验结构怎样进入统一分档、各类
预测结构使用什么阈值仍需算法负责人确认。在此之前只能保存原始质量事实，不能生成正式生产分档。

## 5. S-04：拓扑预测

### 它解决什么问题

S-04 判断蛋白是否为膜蛋白，并标出哪些序列区段可能穿过细胞膜、位于膜内侧、膜外侧或属于信号
肽等类型。候选工具是 DeepTMHMM。

### 它怎样工作

DeepTMHMM 主要从氨基酸序列本身识别具有膜环境特征的区段。它可以处理常见的 alpha 螺旋跨膜
蛋白，也能识别 beta barrel 等膜蛋白类型。输出不只是“是或否”，还包括逐残基标签、跨膜区段、
跨膜次数和相关概率。

### 为什么它重要

膜内区域和暴露在水环境中的区域受到的物理限制不同。若后续把膜内残基当成普通表面残基修改，
可能破坏蛋白插膜、折叠或功能。项目后续还有膜蛋白设计门控：没有得到明确确认时，膜蛋白或低
可信结构可能跳过全蛋白重新设计。

### 它不负责什么

- 不告诉我们整个蛋白位于细菌细胞的哪个区域；那是当前 P0 范围外 S-06 的问题。
- 不生成三维结构。
- 不仅仅返回一个膜蛋白布尔值，原始区段和逐残基证据也必须保留。
- 不允许语言模型根据蛋白名称猜测是否为膜蛋白。

### 当前项目状态

S-04 尚未开始真实工具实测。除输出映射和边界样本外，DeepTMHMM 的本地部署还存在使用性质与
许可证门禁；许可未确认前不能形成生产交付镜像。

## 6. S-11：溶剂可及面积与相对暴露程度

### 它解决什么问题

蛋白折叠以后，有些残基暴露在水环境中，有些埋在蛋白内部。S-11 使用 FreeSASA 计算溶剂能够
接触到的表面积，并据此提供每个残基的绝对 SASA 和相对 RSA。

可以把它想象成让一个代表水分子的探针球沿蛋白表面滚动：探针能够接触到的区域更暴露，接触
不到的区域更可能埋在内部。

### 它怎样工作

S-11 必须读取三维结构坐标。计算之前，还要先把用户序列中的每个位置与结构文件中的实际残基
对应起来，因为实验结构可能缺少一段坐标，也可能只包含目标序列的一部分。

完成映射后，FreeSASA 可以按原子、残基、链和整个结构计算表面积。项目还需要固定探针大小、
原子半径口径、链与配体处理、多模型行为等参数，避免不同运行使用不同默认值。

### 为什么它重要

RSA 会被后续多个步骤复用，例如判断标签是否暴露、辅助结构表位分析，以及区分更像蛋白核心的
残基和更像表面的残基。如果残基编号映射错误，表面信息就可能被写到错误的序列位置，影响后续
设计权限和验证结果。

S-11 的逐残基结果通常比一个简单分档更长，但规模主要随蛋白长度和结构中的链数增长，不会像
S-07 那样因为数据库候选数量而无限扩张。

### 它不负责什么

- 不预测三维结构，只分析已经得到的结构坐标。
- FreeSASA 成功运行不等于结果一定对应正确的目标序列。
- 不得在目标链不明确或关键残基无法映射时静默继续。
- 不自行决定“暴露”和“埋藏”的科学阈值；它首先提供可追溯的计算事实。

### 当前项目状态

S-11 尚未开始真实实现，并受到 OI-015 阻塞。算法与后端负责人需要先确认序列—结构一致性检查、
允许的缺口和映射失败行为，然后才能把 FreeSASA 结果用于正式流程。

## 7. 已明确移出一期的能力：S-06 细菌亚细胞定位

S-06/PSORTb 不属于当前 P0 或一期工作范围。保留本节只为解释旧方案和历史范围差异，不表示
当前或后续一期阶段会实现、发布或交付该工具。2026-09-03 最新一期 18 节点基线已经关闭
OI-019 的范围问题：S-06 正式排除；旧算法图和 v10.5 SOP 中的细菌路径只作历史证据。

### 它解决什么问题

同样是细菌蛋白，可能位于细胞质、细胞膜、周质、细胞壁或细胞外等不同位置。S-06 使用 PSORTb
预测蛋白最可能出现在哪里，为后续理解它是否容易被外界接触、可能承担什么功能提供基础信息。

若未来版本由用户明确重新纳入，须另行建立范围基线、契约、G0 和验收；旧规则不能自动恢复。

### 它怎样工作

PSORTb 读取蛋白序列，但还必须知道应该使用哪种生物类别模型，例如 Gram-positive、
Gram-negative 或 Archaea。不同类别的细胞结构不同，因此不能只知道“它是细菌”就随便选择一个
模型。

当前项目必须由受控输入、可靠的物种分类服务或算法负责人批准的其他确定性来源提供这个信息。
语言模型不能根据蛋白名称或描述猜测 Gram 类型。

### 为什么它重要

蛋白位于细胞内部还是表面，会影响后续对可接近性、抗原暴露和功能背景的解释。如果模型选择错了，
同一段序列可能得到错误的定位结论；如果把“不确定”强制改成某个位置，也会制造虚假信息。

PSORTb 结果通常比结构文件小，主要包括预测位置、得分、使用的生物类别模型、警告和原始报告。

### 它不负责什么

- 不判断具体哪些残基穿膜；这是 S-04 的工作。
- 不适用于所有非细菌目标。
- 不把 Unknown 或多个可能位置强行改成单一确定答案。
- 不单独决定一个蛋白是否适合作为最终设计目标。

### 当前项目状态

S-06 已排除出一期和当前 P0，不作为发布包或冻结条件。只有未来用户明确建立新范围基线后，
才可能重启 Gram/Archaea 输入、输出映射、ToolSpec、容器安全和可重复构建评审。

## 8. 三组最容易混淆的能力（含范围外 S-07/S-06）

### S-07 与 S-08

- S-07 是“去外部资料库找已经存在的结构”，已因甲方内网条件移出一期。
- S-08 是“甲方未提供结构时，用其序列计算一个结构”；AlphaFold3/ESMFold2 是节点 01 仅有的科学工具。

### S-09 与 S-11

- S-09 回答“这份结构整体有多可信”。
- S-11 回答“结构中的每个残基有多暴露”。

高可信结构也会同时包含表面残基和内部残基，所以这两个问题不能互相代替。

### S-04 与当前范围外的 S-06

- S-04 回答“蛋白序列中的哪些区段穿过膜”。
- S-06 回答“整个细菌蛋白可能位于细胞的哪个区域”。

一个蛋白的跨膜方式和它在细胞中的总体位置有关，但不是同一个问题。

## 9. P0 最终应该交出什么

P0 完成后，不应该只给出四个步骤各自的一堆文件，而应形成一份可以追溯的基础证据包：

- 甲方输入的版本、来源与哈希，以及输入是否通过确定性校验；
- 是否使用甲方可选结构；无结构时 AlphaFold3/ESMFold2 采用哪个内网部署 profile、产生了什么预测结构；
- 结构质量事实和最终质量分档；
- 膜拓扑、跨膜区段和相关警告；
- 结构可用时的逐残基 RSA，或者为什么没有计算；
- 所有关键原始文件、版本、参数和校验信息的引用。

阶段 1 以后使用的是这份整理过的证据，而不是让语言模型直接阅读原始文件并自行作科学判断。

## 10. 常用词语

| 词语 | 通俗解释 |
|---|---|
| 蛋白序列 | 由氨基酸字母组成的一维信息，是本项目最原始的目标事实 |
| 残基 | 蛋白链中的一个氨基酸位置 |
| 三维结构 | 蛋白中原子或残基在空间中的位置 |
| 实验结构 | 通过晶体学、冷冻电镜、核磁等实验方法获得的结构 |
| 预测结构 | 计算模型根据序列推算出的结构，不等同于实验观测 |
| PDB entry | RCSB PDB 中的一条结构记录，内部可能包含多个蛋白实体和多条链 |
| chain | 一个结构文件中的一条分子链 |
| 坐标覆盖 | 目标序列中有多少残基在结构文件里确实具有三维坐标 |
| pLDDT | 预测模型给出的逐残基可信度指标之一 |
| PAE | 预测模型对不同区域相对位置不确定性的表达之一 |
| SASA | 溶剂能够接触到的表面积 |
| RSA | 把 SASA 按残基参考值归一化后得到的相对暴露程度 |
| 拓扑 | 蛋白各区段相对于细胞膜的排列方式 |
