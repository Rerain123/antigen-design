# 已部署蛋白工具接口、调用与测试手册

> 文档版本：1.0  
> 最后更新：2026-08-19  
> 适用服务器：`10.11.46.133`  
> 运行平台：Ubuntu 24.04，Linux x86_64，CPU 节点  
> 文档范围：HADDOCK3、MHCflurry、ProteinMPNN、ThermoMPNN

## 1. 关键结论

目前四个工具均已在服务器上安装并通过部署验收，但它们当前提供的是**服务器本地命令行接口**；MHCflurry 另外提供可直接导入的 Python API。

当前没有常驻 HTTP/REST 服务、没有开放 API 端口，也没有类似 `http://10.11.46.133:端口/...` 的调用地址。业务程序应通过以下两种方式之一调用：

1. 在服务器上执行本文列出的命令行入口；
2. 由 Python、Java 或其他后端程序以子进程方式调用命令行入口，并读取输出文件。

如需从其他服务器通过 HTTP 调用，应另行部署统一 API 服务。本文第 8 节给出了建议的 REST API 契约，但该部分是**设计建议，尚未部署**。

### 2.2 建议的业务任务目录

正式任务不要写入 `/data/ai4s/apps`、`/data/ai4s/envs` 或 `/data/ai4s/tests`。建议每次调用创建独立目录：

```text
/data/ai4s/jobs/<tool>/<job_id>/
├── input/
├── output/
└── logs/
```

其中 `<job_id>` 应由调用方生成，并确保不会与其他并发任务重复。

### 2.3 通用调用规则

- 推荐直接使用环境内可执行文件的绝对路径，不依赖当前 Shell 是否执行过 `conda activate`。
- 每次调用使用独立输出目录，避免并发任务互相覆盖。
- 进程退出码为 `0` 仅代表命令正常结束；调用方还应检查预期输出文件是否存在且非空。
- 四个工具推理阶段均不需要访问互联网，模型文件已存放在服务器上。
- 当前节点没有 NVIDIA GPU，`torch.cuda.is_available()` 返回 `False` 是预期状态。
- 不应把用户传入的字符串直接拼接成 Shell 命令；后端程序应使用参数数组调用子进程。

## 3. HADDOCK3

### 3.1 功能与接口

HADDOCK3 用于蛋白质、核酸及其他生物分子之间的约束驱动对接。它以工作流配置文件作为主要输入。

| 项目 | 内容 |
|---|---|
| 接口类型 | 命令行工作流接口 |
| 可执行文件 | `/data/ai4s/envs/haddock3/bin/haddock3` |
| 配置检查工具 | `/data/ai4s/envs/haddock3/bin/haddock-cfg` |
| 主要输入 | HADDOCK3 `.cfg` 配置文件、两个或多个 PDB 文件、可选约束文件 |
| 主要输出 | `run_dir` 下各工作流模块目录、模型、评分和日志 |
| 稳定 Python API | 不建议将内部模块作为业务接口；优先调用 CLI |

### 3.2 版本与帮助

```bash
/data/ai4s/envs/haddock3/bin/haddock3 --version
```

```bash
/data/ai4s/envs/haddock3/bin/haddock3 -h
```

查看某个工作流模块的默认参数，例如 `rigidbody`：

```bash
/data/ai4s/envs/haddock3/bin/haddock-cfg -m rigidbody
```

### 3.3 最小对接调用样例

先准备两个输入结构：

```text
/data/ai4s/jobs/haddock3/demo/input/receptor.pdb
/data/ai4s/jobs/haddock3/demo/input/ligand.pdb
```

创建 `/data/ai4s/jobs/haddock3/demo/input/workflow.cfg`：

```toml
run_dir = "/data/ai4s/jobs/haddock3/demo/output/run"
mode = "local"
ncores = 8

molecules = [
    "/data/ai4s/jobs/haddock3/demo/input/receptor.pdb",
    "/data/ai4s/jobs/haddock3/demo/input/ligand.pdb",
]

[topoaa]

[rigidbody]
sampling = 20

[caprieval]
```

执行：

```bash
mkdir -p /data/ai4s/jobs/haddock3/demo/output
/data/ai4s/envs/haddock3/bin/haddock3 /data/ai4s/jobs/haddock3/demo/input/workflow.cfg
```

说明：

- 上述 `sampling = 20` 用于小规模连通性测试，不代表正式计算的推荐采样量。
- 若有实验约束，可在相应模块中增加 `ambig_fname = "约束文件路径"`。
- HADDOCK3 按配置文件中模块出现的顺序执行工作流。

### 3.4 结果验收

```bash
test -d /data/ai4s/jobs/haddock3/demo/output/run && echo HADDOCK3_RUN_DIR_OK
```

查看运行日志和模块目录：

```bash
find /data/ai4s/jobs/haddock3/demo/output/run -maxdepth 2 -type f | head -n 30
```

HADDOCK3 是四个工具中计算时间最长、输出结构最复杂的一项。生产集成时应作为异步任务处理，不应让 HTTP 请求持续等待整个对接过程。

### 3.5 后端程序调用示例

```python
import subprocess

command = [
    "/data/ai4s/envs/haddock3/bin/haddock3",
    "/data/ai4s/jobs/haddock3/demo/input/workflow.cfg",
]

result = subprocess.run(
    command,
    check=True,
    text=True,
    stdout=subprocess.PIPE,
    stderr=subprocess.STDOUT,
)
print(result.stdout)
```

## 4. MHCflurry

### 4.1 功能与接口

MHCflurry 用于 MHC I 类分子的肽结合亲和力、抗原加工和呈递概率预测。

| 项目 | 内容 |
|---|---|
| 接口类型 | 命令行接口、Python API |
| Conda 环境 | `/data/ai4s/envs/mhcflurry` |
| 命令行入口 | `/data/ai4s/envs/mhcflurry/bin/mhcflurry-predict` |
| 蛋白扫描入口 | `/data/ai4s/envs/mhcflurry/bin/mhcflurry-predict-scan` |
| 模型数据根目录 | `/data/ai4s/data/mhcflurry` |
| 呈递模型目录 | `/data/ai4s/data/mhcflurry/2.2.0/models_class1_presentation` |
| 主要输入 | MHC I 等位基因和肽序列，或包含它们的 CSV |
| 主要输出 | CSV |

每次调用都应显式设置：

```bash
export MHCFLURRY_DATA_DIR=/data/ai4s/data/mhcflurry
```

也可以仅给单条命令设置该变量，如下方样例所示。

### 4.2 命令行测试样例

```bash
mkdir -p /data/ai4s/jobs/mhcflurry/demo/output
MHCFLURRY_DATA_DIR=/data/ai4s/data/mhcflurry /data/ai4s/envs/mhcflurry/bin/mhcflurry-predict --alleles HLA-A0201 HLA-A0301 --peptides SIINFEKL SIINFEKD SIINFEKQ --out /data/ai4s/jobs/mhcflurry/demo/output/predictions.csv
```

验收：

```bash
test -s /data/ai4s/jobs/mhcflurry/demo/output/predictions.csv && echo MHCFLURRY_OK
head -n 5 /data/ai4s/jobs/mhcflurry/demo/output/predictions.csv
```

```text

```

### 4.3 CSV 批量输入

输入文件示例：

```csv
allele,peptide
HLA-A0201,SIINFEKL
HLA-A0201,SIINFEKD
HLA-A0301,SIINFEKQ
```

调用：

```bash
MHCFLURRY_DATA_DIR=/data/ai4s/data/mhcflurry /data/ai4s/envs/mhcflurry/bin/mhcflurry-predict /data/ai4s/jobs/mhcflurry/demo/input/peptides.csv --out /data/ai4s/jobs/mhcflurry/demo/output/predictions.csv
```

常见输出字段：

| 字段 | 含义 | 排序方向 |
|---|---|---|
| `mhcflurry_affinity` | 预测结合亲和力，单位 nM | 越低通常表示结合越强 |
| `mhcflurry_affinity_percentile` | 等位基因内亲和力百分位 | 越低越强 |
| `mhcflurry_processing_score` | 抗原加工分数 | 越高越强 |
| `mhcflurry_presentation_score` | 综合呈递分数 | 越高越强 |
| `mhcflurry_presentation_percentile` | 呈递百分位 | 越低越强 |

### 4.4 Python API 样例

```python
import os

os.environ["MHCFLURRY_DATA_DIR"] = "/data/ai4s/data/mhcflurry"

from mhcflurry import Class1PresentationPredictor

predictor = Class1PresentationPredictor.load()
result = predictor.predict(
    peptides=["SIINFEKL", "SIINFEKD", "SIINFEKQ"],
    alleles=["HLA-A0201", "HLA-A0301"],
    verbose=0,
)

print(result)
result.to_csv("/data/ai4s/jobs/mhcflurry/demo/output/python_predictions.csv", index=False)
```

注意：Python API 中以列表传入多个 `alleles` 时，通常表示一个样本的 MHC 基因型，并返回每条肽在这些等位基因中的最佳结果；而命令行样例会对命令行列出的等位基因和肽进行组合预测。集成时应根据业务含义选择调用形式。

### 4.5 查询模型能力

```bash
MHCFLURRY_DATA_DIR=/data/ai4s/data/mhcflurry /data/ai4s/envs/mhcflurry/bin/mhcflurry-predict --list-supported-alleles
```


## 5. ProteinMPNN

### 5.1 功能与接口

ProteinMPNN 根据给定蛋白质骨架设计氨基酸序列，可指定需要重新设计的链、固定位置和采样参数。

| 项目 | 内容 |
|---|---|
| 接口类型 | Python 命令行脚本 |
| Python | `/data/ai4s/envs/proteinmpnn/bin/python` |
| 主脚本 | `/data/ai4s/apps/proteinmpnn/protein_mpnn_run.py` |
| 应用目录 | `/data/ai4s/apps/proteinmpnn` |
| 默认模型目录 | `/data/ai4s/apps/proteinmpnn/vanilla_model_weights` |
| 已验收模型 | `v_48_020.pt` |
| 主要输入 | PDB 骨架、待设计链及采样参数 |
| 主要输出 | FASTA；可选 NPY 分数和概率文件 |
| 稳定 Python API | 官方主要入口为脚本；业务代码建议通过子进程调用 |

### 5.3 主要参数

| 参数 | 说明 |
|---|---|
| `--pdb_path` | 单个输入 PDB 文件 |
| `--pdb_path_chains` | 需要设计的链，多个链以空格分隔 |
| `--out_folder` | 输出根目录 |
| `--num_seq_per_target` | 每个目标生成的序列数 |
| `--sampling_temp` | 采样温度；较低更保守，较高更多样 |
| `--seed` | 随机种子；用于可重复测试 |
| `--batch_size` | 批量大小；当前 CPU 部署建议从 `1` 开始 |
| `--model_name` | 模型名称；默认 `v_48_020` |
| `--score_only 1` | 仅对已有骨架—序列组合评分 |
| `--save_score 1` | 保存每条序列的分数文件 |
| `--save_probs 1` | 保存逐位置概率 |

查看全部参数：


### 6.3 参数和输出字段

主要参数：

| 参数 | 说明 |
|---|---|
| `--pdb` | 输入 PDB 文件 |
| `--chain` | 要扫描的链 ID；默认 `A` |
| `--model_path` | ThermoMPNN 模型文件 |
| `--out_dir` | 输出目录 |

主要输出字段：

| 字段 | 说明 |
|---|---|

| `Dataset` | 由输入 PDB 文件名生成的任务标识 |

`custom_inference.py` 会扫描整条链，而不是只预测调用方指定的一条突变，因此长链的输出行数和运行时间会随链长增长。对 `ddG_pred` 作生物学阈值判断前，应统一项目采用的 ΔΔG 符号定义和筛选规则。

## 8. 统一 HTTP API 设计建议（尚未部署）

如果需要让智能体、网页或其他服务器通过网络调用，建议在这四个命令行工具外增加一个独立的 API 服务，并使用异步任务模型。

### 8.1 建议端点

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/api/v1/health` | API 服务和四个工具健康状态 |
| `GET` | `/api/v1/tools` | 工具版本、能力和参数定义 |
| `POST` | `/api/v1/jobs` | 上传输入并创建任务 |
| `GET` | `/api/v1/jobs/{job_id}` | 查询排队、运行、成功或失败状态 |
| `GET` | `/api/v1/jobs/{job_id}/artifacts` | 列出结果文件 |
| `GET` | `/api/v1/jobs/{job_id}/artifacts/{name}` | 下载单个结果文件 |
| `POST` | `/api/v1/jobs/{job_id}/cancel` | 取消尚未结束的任务 |

### 8.2 创建任务请求

建议使用 `multipart/form-data`：

```text
tool = proteinmpnn
parameters = {"chains":"A B","num_sequences":2,"temperature":0.1,"seed":37}
input_file = target.pdb
```

统一响应示例：

```json
{
  "job_id": "01JEXAMPLE8T0S5YQ7R",
  "tool": "proteinmpnn",
  "status": "queued",
  "created_at": "2026-08-19T10:00:00+08:00"
}
```

任务完成后的状态示例：

```json
{
  "job_id": "01JEXAMPLE8T0S5YQ7R",
  "tool": "proteinmpnn",
  "status": "succeeded",
  "exit_code": 0,
  "artifacts": [
    {
      "name": "3HTN.fa",
      "media_type": "text/plain"
    }
  ]
}
```

### 8.3 实现约束

- API 服务不应以 `root` 用户运行。
- 仅允许白名单参数，不允许客户端提交任意命令或任意服务器路径。
- 每个任务必须使用独立工作目录，并限制输入文件类型、大小、CPU、内存和运行时间。
- HADDOCK3 必须异步执行；其他工具也建议统一异步，以便排队、取消和保存日志。
- API 返回任务 ID，不直接暴露服务器绝对路径。
- 结果下载前应校验任务所有者或访问令牌。
- 应为每次调用记录工具版本、模型版本、参数、随机种子、开始时间、结束时间和退出码。

## 9. 常见问题

### 9.1 显示 `CUDA可用: False`

这是当前 CPU 节点的正常状态。四个已部署工具均按 CPU 模式验证成功。

### 9.2 MHCflurry 报找不到模型

确认调用命令带有：

```bash
MHCFLURRY_DATA_DIR=/data/ai4s/data/mhcflurry
```

并检查模型目录：

```bash
test -d /data/ai4s/data/mhcflurry/2.2.0/models_class1_presentation && echo MODEL_DIR_OK
```

### 9.3 命令结束但没有结果

同时检查：

1. 子进程退出码；
2. 标准输出和标准错误；
3. 预期文件是否存在且非空；
4. 输出目录是否与本次任务唯一对应；
5. 输入 PDB 的链 ID 是否与参数一致。

### 9.4 是否可以直接开放安装目录给多个调用方

不建议。`apps`、`envs`、`data` 应只读，所有业务输入和结果应进入独立的 `jobs` 目录。统一 API 服务还应使用专用低权限账号。
